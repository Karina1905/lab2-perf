# Лабораторна робота №2. Performance Measurement and Analysis

Бабінова Карина, група ТК-31

Програма — множення матриць 1536×1536 на C++ плюс кілька простих операцій з векторами (saxpy, сума масиву).
Досліджуємо, як ключі компілятора (`-O0`, `-O2`, `-O3`) і зміна порядку циклів (ijk → ikj) впливають на час,
кількість інструкцій, енергоспоживання і асемблерний код.

Усе виконувалось на MacBook Pro (Apple M3 Pro), компілятор Apple clang 15. Оскільки на macOS немає `perf`,
використано аналоги: `sample` + FlameGraph, `/usr/bin/time -l`, `powermetrics`.

## Як запустити

```bash
./scripts/setup.sh          # перевірка інструментів, завантаження FlameGraph
make                        # збирає всі варіанти програми і асемблер у asm/
./bin/prog_O0               # запуск без оптимізації
./bin/prog_O3               # запуск з -O3
./scripts/04_compare.sh     # FlameGraph, статистика і енергія для -O0, -O3 без векторизації, -O3
python3 scripts/05_timing.py  # таблиці часу (7 запусків)
```

## Структура

| Що | Де |

## Основні результати

| | -O0 | -O3 без векторизації | -O3 |
|---|---|---|---|
| час, с | 12.73 | 2.01 | 0.52 |
| інструкцій, млрд | 190.7 | 30.4 | 4.2 |
| IPC | 5.4 | 5.4 | 2.9 |
| енергія системи, Дж | 42.4 | 7.6 | 2.0 |

- Програма з `-O3` працює в 24.6 раза швидше і витрачає в ~20 разів менше енергії.
- Множення матриць: тільки `-O3` на звичайному порядку ijk дає 1.6×, а перестановка циклів (ikj) разом з `-O3` — 22.7×.
- На `-O0` цикли `for (int x : v)` перетворюються на виклики функцій ітераторів (≈ 36% часу на FlameGraph), на `-O3` вони зникають.
- На `-O3` компілятор використовує векторні інструкції NEON (`fmla.4s`, 4 числа за раз).
